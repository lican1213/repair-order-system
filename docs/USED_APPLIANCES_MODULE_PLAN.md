# 二手家电展示橱窗模块规划

**规划版本：** v1.3  
**规划日期：** 2026-05-04  
**当前状态：** 已实现，详见 `docs/USED_APPLIANCES_IMPLEMENTATION_REPORT.md`  
**模块定位：** 二手家电信息展示橱窗，不是商城系统

## 1. 是否建议开发

已作为 **v1.3 极简展示橱窗** 实现。

该模块与现有维修业务有自然关联：维修店老板可能有少量回收、翻新或置换的二手家电，需要一个简单展示入口供客户浏览。但它必须保持为“展示 + 电话咨询”，不能扩展成在线交易、库存、订单或商城系统。

未混入 v1.2。v1.3 单独新增数据表、后台管理、公开列表和图片上传能力。

## 2. 业务价值

- 增加维修店的附加曝光：客户报修或查看价格时，可顺手看到店内可售二手家电。
- 帮助老板低成本展示少量库存：不用朋友圈反复发图，也不用维护复杂商城。
- 促进电话咨询：客户看到感兴趣的商品后直接打电话确认价格、成色、库存和配送。
- 保持小店业务习惯：最终仍由电话沟通和线下交易确认，不改变现有经营流程。

## 3. 风险和技术债

- **库存时效风险：** 二手家电库存变化快，页面可能展示已售商品，需要老板及时维护状态。
- **价格争议风险：** 页面价格可能滞后，必须明确“仅供参考，以电话确认为准”。
- **功能膨胀风险：** 容易被继续要求加购物车、订单、支付、留言、SKU、库存流水，必须在版本边界中禁止。
- **图片存储增长：** 商品图片会进入备份范围，长期可能增加 `uploads/` 和备份体积。
- **孤儿图片风险：** 后台上传图片后若未保存商品，可能产生未关联图片，需要后续清理策略或接受少量冗余。
- **无迁移系统技术债：** 当前项目使用 SQLite 自动建表思路，没有 Alembic。新增表需要谨慎设计初始化和备份回滚。
- **公开展示质量风险：** 图片、标题和描述由老板手填，可能出现信息不完整或格式不统一，需要后台表单约束。

## 4. 明确不做内容

v1.3 二手家电展示橱窗明确不做：

- 不做在线下单
- 不做在线交易
- 不做在线支付
- 不做购物车
- 不做客户留言、询价表单或在线客服
- 不做复杂库存管理、库存流水、入库出库记录
- 不做多规格 SKU
- 不做会员价、优惠券、促销系统
- 不做配送费计算
- 不做订单状态流转
- 不做交易闭环
- 不接入 AI 客服、AI 诊断、AI 报价
- 不做微信小程序
- 不把项目改造成商城系统

## 5. 推荐版本号

推荐版本：**v1.3**

理由：

- v1.2 已预留给店铺信息编辑和保修二维码下载。
- 二手家电展示是新增业务模块，需要新增表、API 和页面，不应作为灰度小修或内容更新插入。
- 独立版本便于上线前单独验收和回滚。

## 6. 数据库设计草案

已新增表：`used_appliances`

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| id | INTEGER | PK, AUTOINCREMENT | 自增主键 |
| title | TEXT | NOT NULL | 商品标题，如“二手海尔 8kg 洗衣机” |
| category | TEXT | NOT NULL | 家电分类，如空调/冰箱/洗衣机/电视/其他 |
| brand_model | TEXT | | 品牌型号 |
| price | TEXT | | 参考价文案，如“800元起 / 面议 / 电话咨询” |
| condition_note | TEXT | | 成色说明，如“八成新，外观轻微划痕” |
| description | TEXT | | 补充说明，不支持富文本 |
| image_paths | TEXT | | 商品图片路径，JSON 数组字符串 |
| status | TEXT | NOT NULL DEFAULT '在售' | 在售 / 已售 / 下架 |
| contact_phone | TEXT | | 咨询电话；为空时使用店铺电话 |
| created_at | DATETIME | DEFAULT CURRENT_TIMESTAMP | 创建时间 |
| updated_at | DATETIME | DEFAULT CURRENT_TIMESTAMP | 更新时间 |

建议索引：

| 索引名 | 字段 | 说明 |
|--------|------|------|
| ix_used_appliances_status | status | 公开列表只查在售，需要按状态过滤 |
| ix_used_appliances_category | category | 后续按分类筛选 |
| ix_used_appliances_created_at | created_at | 列表按发布时间倒序 |

状态枚举应集中管理：

- 后端：`backend/app/constants.py`
- 前端：`frontend/src/constants.ts`

图片路径规则：

```json
["/uploads/used-appliances/abc123.webp"]
```

## 7. 后端 API 草案

### 公开接口（无需登录）

#### GET /api/used-appliances

客户查看二手家电列表。

查询参数草案：

| 参数 | 类型 | 默认 | 说明 |
|------|------|------|------|
| category | string | 无 | 按分类筛选 |
| include_sold | boolean | false | 是否展示已售商品 |
| page | int | 1 | 页码 |
| page_size | int | 20 | 每页数量，建议最大 50 |

公开展示规则：

- 默认只返回 `status=在售` 的商品。
- `include_sold=true` 时可返回 `在售 + 已售`。
- 永远不返回 `status=下架` 的商品。
- 不返回后台内部字段以外的信息；该表本身不应存储客户隐私。

响应字段草案：

```json
{
  "items": [
    {
      "id": 1,
      "title": "二手海尔 8kg 洗衣机",
      "category": "洗衣机",
      "brand_model": "海尔 XQB80",
      "price": 580,
      "condition_note": "八成新，正常使用",
      "description": "适合出租房或临时过渡使用",
      "image_paths": ["/uploads/used-appliances/abc123.webp"],
      "status": "在售",
      "contact_phone": "13800138000",
      "created_at": "2026-05-04T10:00:00"
    }
  ],
  "total": 1,
  "page": 1,
  "page_size": 20
}
```

### 后台接口（需 JWT）

#### GET /api/admin/used-appliances

后台商品列表，支持 `status`、`category`、`keyword`、`page`、`page_size`。

#### POST /api/admin/used-appliances

新建商品。必填：`title`、`category`、`status`。建议后台默认状态为 `在售`。

#### GET /api/admin/used-appliances/{id}

后台查看商品详情。

#### PATCH /api/admin/used-appliances/{id}

更新商品信息或切换状态。

#### POST /api/upload/used

后台上传商品图片，需 JWT。复用现有上传校验规则，保存到 `/uploads/used/`。

不建议 v1.3 做硬删除接口。下架和已售用状态表达，避免误删导致图片、展示和审计困难。

## 8. 前端页面草案

### 客户公开页面：/used

页面目标：客户快速查看当前可咨询的二手家电，并打电话确认。

建议内容：

- 顶部展示店铺名称、咨询电话和“电话咨询”按钮。
- 商品卡片列表：图片、标题、分类、品牌型号、参考价、成色说明、状态。
- 默认只展示在售商品。
- 可选开关：“显示已售”，默认关闭。
- 空状态：暂无二手家电，可电话咨询是否有新货。
- 页面底部固定免责声明：

> 二手家电价格、成色和库存变动较快，页面信息仅供参考，具体以电话沟通确认为准。

不建议 v1.3 做单独商品详情页。公开端可以先用列表卡片展示完整信息，减少路由和页面复杂度。

## 9. 后台管理页面草案

### /admin/used-appliances

后台列表页。

建议能力：

- 查看全部商品：在售 / 已售 / 下架。
- 按状态筛选。
- 按分类筛选。
- 搜索标题、品牌型号。
- 快捷操作：标记已售、下架、重新上架。
- 入口：新增二手家电。

### /admin/used-appliances/new

新增商品页。

字段：

- 标题（必填）
- 分类（必填）
- 品牌型号
- 参考价（整数元，可为空）
- 成色说明
- 详细描述
- 商品图片，最多 5 张
- 状态，默认在售
- 咨询电话，默认留空使用店铺电话

### /admin/used-appliances/:id

编辑商品页。

能力：

- 修改基础信息。
- 增删图片路径。
- 切换状态：在售 / 已售 / 下架。
- 保存后返回列表。

后台页面应继续保持手机优先，按钮要大、状态切换要直接，避免复杂表格。

## 10. 图片上传复用方案

推荐方案：

- 复用现有图片校验规则：`jpg/jpeg/png/webp`、单张最大 5MB、最多 5 张、随机文件名。
- 不复用公开报修上传接口 `/api/public/upload`，因为该接口无需登录且写入 `orders/temp/`。
- 新增后台受保护接口 `/api/upload/used-appliances`，需要 JWT。
- 图片保存目录使用 `backend/uploads/used-appliances/`。
- 返回路径使用 `/uploads/used-appliances/<filename>`，继续由现有 `/uploads/*` 静态挂载公开访问。
- `used_appliances.image_paths` 使用 JSON 数组字符串保存。

后续可选增强：

- 若孤儿图片明显增长，再扩展 `scripts/cleanup_temp_images.py` 或新增清理脚本。
- 如果要避免孤儿图片，可使用 `uploads/used-appliances/temp/`，保存商品时移动到正式目录；但 v1.3 初版会增加实现复杂度。

## 11. 权限要求

- 客户公开页面 `/used` 无需登录，只读。
- 公开接口只允许读取在售商品，默认不展示已售，不展示下架。
- 后台管理页面和后台 API 必须使用现有 JWT 认证。
- 只有 admin 可以新增、编辑、标记已售、下架。
- 图片上传必须走后台 JWT 接口，不开放匿名商品图片上传。
- 不新增客户账号，不新增多员工权限。

## 12. 验收标准

- 客户访问 `/used` 能看到所有 `status=在售` 的商品。
- 默认不展示 `已售` 商品；开启“显示已售”后才展示已售。
- 永远不展示 `下架` 商品。
- 商品卡片展示标题、分类、品牌型号、参考价、成色、图片和电话咨询入口。
- 页面清晰展示免责声明。
- 后台 admin 能新增、编辑、标记已售、下架和重新上架商品。
- 后台上传商品图片成功后，公开页面可以正常显示。
- 未登录访问后台二手家电页面会跳转登录。
- 公开 API 不返回任何客户订单隐私字段。
- 不存在购物车、下单、支付、留言、库存流水或 SKU 功能入口。

## 13. 测试清单

### 后端测试

- 新建商品：必填字段缺失返回 422。
- 新建商品：`status` 只能是 在售 / 已售 / 下架。
- 列表接口：默认只返回在售。
- 列表接口：`include_sold=true` 返回在售和已售。
- 列表接口：下架商品永远不返回公开接口。
- 后台列表：admin 可看到全部状态。
- 未登录调用后台接口返回 401。
- 上传接口：未登录返回 401。
- 上传接口：非法 MIME type 或扩展名返回 415。
- 上传接口：超出大小返回 413。
- 上传接口：超过数量返回 400。

### 前端测试

- `/used` 移动端首屏可直接看商品和电话入口。
- `/used` 无商品时展示空状态。
- 商品图片为空时有稳定占位，不挤压布局。
- 长标题、长品牌型号、长描述不撑破卡片。
- 参考价为空时展示“电话咨询”。
- “显示已售”默认关闭，开启后已售商品有明确状态标识。
- 后台新增、编辑、保存、返回列表流程可用。
- 后台状态切换后公开页面展示规则正确。

### 回归测试

- `/repair` 报修流程不受影响。
- `/pricing` 清洗价格表不受影响。
- `/warranty/t/:token` 保修查询不受影响。
- `/admin/orders` 工单管理不受影响。
- 生产构建后 SPA fallback 正常。
- `/uploads/*` 图片访问正常。

## 14. 回滚方案

上线前准备：

- 上线前完整备份 `backend/data/repair.db` 和 `backend/uploads/`。
- 记录发布版本和前端构建产物。

功能级回滚：

- 从前端移除或隐藏 `/used` 入口。
- 将所有商品状态改为 `下架`，公开页面即不展示商品。
- 停用后台二手家电管理入口。

版本级回滚：

- 回滚到上一版后端和前端构建产物。
- 数据库新增表可保留，不影响旧版本读取。
- 已上传的 `/uploads/used-appliances/` 图片可保留到后续人工清理。

如果未来实现使用自动建表，回滚时不建议自动 drop 表，避免误删老板已录入的商品信息。

## 15. 上线前需要确认的问题

1. 店里是否真的有稳定的二手家电来源，还是偶尔才有一两台。
2. 老板是否愿意在卖出后及时标记“已售”或“下架”。
3. 是否展示参考价，还是统一显示“电话咨询”。
4. 咨询电话是否统一使用店铺电话，还是允许每个商品单独设置。
5. 是否需要展示已售商品作为可信度背书；如果展示，默认仍应关闭。
6. 商品分类是否复用现有家电类型，是否需要新增“二手空调/二手冰箱”等分类文案。
7. 商品图片最多 5 张是否足够。
8. `/used` 入口放在哪里：报修页、价格表页、后台生成二维码，还是暂时只通过链接分享。
9. 是否接受没有商品详情页，所有信息先在列表卡片中展示。
10. 上线初期是否准备至少 3 个真实商品，避免客户看到空页面。

## 规划结论

已按 **v1.3 极简展示橱窗** 实现。

实现时必须坚持“展示 + 电话咨询”的边界，不做交易闭环，不做商城能力。
