## 审计 Prompt

你是独立 QA 审计员。请严格对照以下原始验收清单，逐项审计 `FINAL_REPORT.html` 中的测试结果。

### 审计标准

对每个清单项，判定三档：

- ✅ **绿（充分验证）**：有截图证据 + 实际操作 + 结果符合预期
- ⚠️ **黄（深度不足）**：只检查了元素存在/UI 加载，未验证行为/数据正确性
- ❌ **红（未覆盖）**：报告中无对应测试，或测试条件不满足导致跳过

### 审计原则

1. **「按钮存在」≠「功能正常」**：只检查元素存在标记为黄，不标记为绿
2. **「条件不满足所以跳过」≠「通过」**：因无数据/无账号导致未实际测试的，标记为红（未覆盖），不是绿
3. **「URL 未变化」可能是失败**：提交后 URL 不变说明可能提交失败，需验证
4. **「前端可能用弹窗」是推测**：没有截图/日志证据的推测不能标记为绿
5. **边界值/校验需要正反两测**：「乱填报错」通过但「合法输入通过」未测，算黄不算绿
6. **多账号场景必须实际换号登录**：只测了 admin 的权限不算覆盖权限矩阵
