# 产品需求文档 (PRD)

## 业务背景

舅舅经营一家小型家电维修商铺，服务附近几个小区，已有稳定客源。当前问题：

- 接单信息分散（微信、电话、口头）
- 容易漏单
- 维修记录不完整
- 收费和保修记录不系统
- 回访靠记忆

## 系统定位

轻量 H5 + 手机后台的家电维修工单系统。

- 客户扫码提交报修
- 老板在手机后台管理订单

## 核心流程

```
客户扫码 → 填写报修 → 老板收到新单 → 联系客户确认 → 上门维修 → 记录结果 → 生成保修凭证
```

## 客户端功能

| # | 功能 | 说明 |
|---|------|------|
| 1 | 首页 | 显示店名、服务范围、联系电话、立即报修按钮 |
| 2 | 报修表单 | 姓名、手机、小区、地址、家电类型、品牌型号、故障描述、希望上门时间、是否紧急、上传照片 |
| 3 | 提交成功页 | 订单编号、师傅联系电话、安全提示 |
| 4 | 保修查询页 | 扫码查看保修信息（只展示公开字段） |

## 老板后台功能

| # | 功能 | 说明 |
|---|------|------|
| 1 | 登录 | 单账号密码登录 |
| 2 | 首页统计 | 今日预约、新报修、待回访、本月已完成、本月收入 |
| 3 | 订单列表 | 按状态/回访/日期筛选、搜索、加载更多 |
| 4 | 订单详情 | 查看完整信息、修改状态、填写维修结果 |
| 5 | 今日预约 | 基于 scheduled_at 查询 |
| 6 | 待回访 | 已完成且未回访的订单 |
| 7 | 一键操作 | 拨打电话、复制地址 |
| 8 | 导出 Excel | 按筛选条件导出订单 |
| 9 | 我的页面 | 店铺信息、退出登录 |

## 订单状态

新报修 → 已联系 → 已预约 → 已上门 → 已完成

分支：需复查、未成交

## 回访状态

未回访 / 已回访 / 客户有问题 / 无需回访

## 非功能需求

| 需求 | 说明 |
|------|------|
| 手机优先 | 老板在手机上使用，按钮大、文字清楚 |
| 无 AI 功能 | 正式系统不依赖大模型 API |
| 隐私保护 | 保修页面不暴露客户手机号、地址、收费 |
| 极简部署 | 单进程运行，适合小店场景 |

## 不做的功能

- AI 客服 / AI 故障诊断 / AI 报价
- 在线支付
- 会员积分
- 商城
- 复杂库存
- 多员工绩效
- 复杂数据大屏
- 微信小程序正式版（v1.3 规划）
